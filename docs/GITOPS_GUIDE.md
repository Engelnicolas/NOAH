# NOAH GitOps Guide (v0.0.9+)

This guide is for operators who already have a v0.0.9 cluster running.
For the one-time migration from v0.0.8, see `MIGRATION_GUIDE.md`.

---

## 1. The model in one paragraph

Git is the source of truth. FluxCD's controllers run inside the
cluster, watch the GitOps repository every 10 minutes, decrypt any
SOPS-protected secrets with the `sops-age` Secret in `flux-system`,
and apply the result. **You don't `kubectl apply` in production —
you `git push`.**

---

## 2. Anatomy of the GitOps repo

```
flux-repo/
├── clusters/production/
│   ├── flux-system/        # auto-generated by `flux bootstrap`
│   ├── infrastructure.yaml # Kustomization → infrastructure/
│   └── apps.yaml           # Kustomization → apps/  (dependsOn: infrastructure)
├── infrastructure/
│   ├── cilium/             # CNI + Hubble + Cilium Ingress
│   ├── cert-manager/       # cert-manager + ClusterIssuer + CF token
│   └── external-dns/       # Cloudflare DNS sync
└── apps/
    ├── authentik/          # SSO (HelmRelease + SOPS-encrypted values)
    ├── headlamp/           # Cluster UI (OIDC via Authentik)
    └── hubble-auth/        # Hubble UI ingress + Authentik proxy
```

`dependsOn` chains:

```
infrastructure  ← apps
  cilium        ← cert-manager  ← external-dns
                                  ← authentik ← headlamp
                                              ← hubble-auth
```

## 3. Common operations

### Add a new application

```bash
mkdir -p flux-repo/apps/myapp
# Drop in: namespace.yaml, helmrepository.yaml, helmrelease.yaml,
# any *.enc.yaml secrets, plus a kustomization.yaml that lists them.
echo "  - myapp" >> flux-repo/apps/kustomization.yaml
sops --encrypt --in-place flux-repo/apps/myapp/secret.enc.yaml
git add -A && git commit -m 'apps: add myapp' && git push
python noah.py flux sync   # optional — Flux will pick it up within 10 min anyway
```

### Update a secret

```bash
sops flux-repo/apps/authentik/values-secret.enc.yaml
git commit -am 'authentik: rotate bootstrap password' && git push
python noah.py flux sync
```

### Pin / pause a HelmRelease (e.g. before a manual chart upgrade)

```yaml
# in flux-repo/apps/<svc>/helmrelease.yaml
spec:
  suspend: true
```

`git push`, do your manual work, then revert to `suspend: false`.

### Force an immediate reconciliation

```bash
python noah.py flux sync                         # everything
flux reconcile helmrelease authentik -n authentik   # one resource
```

### Watch what's happening

```bash
python noah.py flux status        # snapshot
python noah.py flux logs -f       # live tail across controllers
python noah.py cluster status     # nodes + etcd + flux roll-up
```

## 4. Secrets workflow (SOPS + Age)

1. **Decrypt** locally: `sops flux-repo/apps/<svc>/<file>.enc.yaml`
2. **Edit** in your $EDITOR (sops re-encrypts on save).
3. **Commit + push** — FluxCD's kustomize-controller decrypts on
   apply using the `sops-age` Secret in `flux-system`.

The `flux-repo/.sops.yaml` `creation_rules` declare which Age public
keys can decrypt — keep at least two recipients (one offline) so
losing `Age/keys.txt` is recoverable.

> **Never** `kubectl create secret --from-literal` against the live
> cluster. FluxCD will treat it as drift and either reset or refuse to
> reconcile.

---

## 5. Tuning reconciliation cadence

Default `interval: 10m` is suitable for most workloads. For secrets
that need to roll out quickly, drop it on the offending Kustomization:

```yaml
spec:
  interval: 1m
```

Don't go below 30 s — the controller will spend more time list-watching
the API than reconciling.

## 6. Cilium-specific notes

* The Cilium HelmRelease lives in `infrastructure/cilium/` and runs in
  `kube-system`. Editing `values:` triggers a chart upgrade.
* Upgrading Cilium across a major version is the **one** workflow
  where you should `suspend: true` first, do the upgrade manually with
  `cilium upgrade`, then unpause.
* Hubble UI is enabled but its built-in ingress is **disabled**;
  authentication is provided by `apps/hubble-auth/`.

## 7. Disaster recovery

| Scenario                              | Recovery                                                     |
|---------------------------------------|--------------------------------------------------------------|
| Cluster gone (single-node)            | Re-run `noah cluster bootstrap` — Flux reconstructs state.   |
| One HA node down                      | Quorum holds; replace node, run `noah cluster add-nodes`.    |
| `Age/keys.txt` lost, backup intact    | Restore backup as `Age/keys.txt`, re-run bootstrap.          |
| Both Age keys lost                    | Secrets are unrecoverable. Restore from a non-SOPS backup.   |
| GitOps repo gone                      | Restore from any clone — Flux re-points and re-reconciles.   |
